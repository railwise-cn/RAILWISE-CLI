# 多智能体工作流

RAILWISE-CLI 的工作流不是单个 AI 助手从头写到尾，而是由 `chief_manager` 拆解任务，再把资料整理、数据校核、计算分析、报告写作和质量审核交给不同智能体协作完成。

## 标准流转

```text
资料识别
  -> 外业数据首检
  -> 计算 / 趋势分析
  -> 规范引用与知识库检索
  -> 报告或表格生成
  -> QA 终审
  -> output/ 交付
```

每一步都应留下可追溯依据：输入文件、工具计算结果、引用标准、审查意见和最终输出路径。

## 典型任务

### 地保监测方案

```bash
railwise run "根据项目资料起草轨道交通控制保护区监测方案，先列资料缺口，再给出章节大纲"
```

触发 `rail-monitoring-plan` skill 后，系统会先判断处于资料收集、初稿、内审还是专家评审阶段，再按阶段加载模板和检查表。

### 运营监测期报

```bash
railwise run -f data/settlement.csv "生成本期运营监测期报，包含异常点、趋势判断和归档清单"
```

触发 `operational-monitoring` skill 后，系统会围绕基准网、沉降、收敛、水平位移、期报、预警和归档逐项处理。

### 交付前审核

```bash
railwise run --agent qa_reviewer "审核 output/latest/reports/report.md，检查规范引用、数值一致性和交付完整性"
```

终审发现阻塞问题时，应退回给原智能体修改，不建议跳过审核直接交付。

## 固定输出目录

推荐所有生成物统一落到项目本地：

```text
output/
  runs/
  wiki/
  latest
```

`runs/` 保存每次任务的草稿、报告、表格、图表和日志；`wiki/` 保存长期复用的项目知识；`latest` 指向最近一次成果，方便工程人员快速找到文件。

## 失败处理

失败时先看三件事：

1. 输入资料是否缺失或格式不匹配。
2. 工具是否返回了明确的限差、解析或导出错误。
3. QA 是否给出阻塞项和修改方向。

修复数据后可以继续当前会话，也可以用 `railwise run --attach <server>` 连接已有本地服务继续处理。
