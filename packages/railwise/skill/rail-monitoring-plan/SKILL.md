# 轨道交通控制保护区监测方案编写 Skill

辅助起草、内审、修订、专家评审《XX 工程施工期间轨道交通 X 号线控制保护区监测方案》全流程。

## 何时使用本 Skill

当用户需要执行以下任一任务时启用：

- 接到新项目、**从零开始起草**监测方案（最常见场景）
- 编制方案前的资料清单准备、立项决策、报价估算
- 已有初稿，准备**内审会议**或撰写内审纪要
- 根据**内审意见 / 专家评审意见** 对方案进行修改并撰写回复表
- 估算监测点数量、监测频率、报警值与停测条件
- 撰写"监测重难点及应对措施"、"预消警流程"、"应急预案"等核心章节
- 校验既有方案是否覆盖运营单位（如宁波市轨道交通集团）所要求的全部章节

## 第一步：判断当前所处阶段（必做）

启动 skill 时**先和用户确认所处阶段**，再决定加载哪份 reference。不要盲目跳到模板填空——同一个方案在不同阶段的关注点完全不同。

> **同时确认监测对象类型**：地下盾构区间 / **高架区间** / 车站 / 出入场线。若是高架（含高架区间、出入场线高架段、车辆段引桥），**强制加载** `references/elevated-line.md`，地下场景下的"收敛"项目不适用，应改为"墩柱倾斜"。

| 阶段 | 用户典型表达 | 主用 reference |
|---|---|---|
| **0 期 资料收集与立项** | "新接了个项目"、"准备写方案"、"还没拿到全部资料" | `references/phase0-intake.md`（高架时叠加 `references/elevated-line.md` §二资料清单） |
| **1 期 初稿起草** | "开始写方案"、"重难点不会写"、"工作量怎么算" | `references/phase1-drafting.md` + `references/key-difficulties.md` + `references/scoping-and-pricing.md`（高架时叠加 `references/elevated-line.md` 全文） |
| **2 期 内审准备** | "明天/下周内审"、"准备内审材料"、"写内审纪要" | `references/phase2-internal-review.md` |
| **3 期 专家评审与修订** | "送审了"、"专家评审意见回复"、"修改意见" | `references/review-checklist.md` + `references/review-response-template.md` |

> **阶段不清晰时的快速判别**：问用户三个问题——(1) 工筹横道图、勘察报告、安评报告是否已收齐？(2) 方案有没有出过初稿？(3) 内审/专审是否已发生？答 1 否= 0 期；1 是 + 2 否= 1 期；2 是 + 内审已发生 + 专审未发生= 2 期；专审已发生= 3 期。

## 各阶段核心动作总览

### 0 期 资料收集与立项决策

详细流程见 `references/phase0-intake.md`，要点：

- **索取资料清单**：用规范化清单一次性问全（避免反复来回），含工程类、勘察类、轨道类、评估类、合同类五大块
- **监测等级判定**：按工程类型 × 影响范围 × 风险等级三轴决策表确定 一/二/三级
- **模板选择**：运营线路 → 模板 A（16 章）；建设期线路 → 模板 B（11–14 章）
- **报价快算**：用 `references/scoping-and-pricing.md` 的公式预估测点、监测次数、人工费

### 1 期 初稿起草

详细流程见 `references/phase1-drafting.md`，建议**起草顺序**（**不要从第 1 章顺写**）：

1. 先写 **3.1 监测范围** 与 **3.4 监测频率分阶段表**——这两节锚定整份方案
2. 再回填 **1.5 施工筹划**（从工筹横道图提取阶段）
3. 写 **5 章 监测点布设** + **3.5 工作量预估**（数量算清楚）
4. **2.3 监测重难点及应对措施**——单独花时间，按 `references/key-difficulties.md` 的"诊断→推演→生成"工作流写
5. **11 章 报警值与预消警**——引用安评报告进行项目化裁剪
6. 最后回填 1.1–1.4（工程概况类）、4 章控制网、6 章监测方法（这些可大段复用）
7. 附图清单先列文字描述，定稿前再补图

**关键纪律**：每节起草前问自己"这一节本项目和上一项目相比有什么不一样？"如果答不上来，就是要么资料没吃透，要么这一节没必要写得那么详细。

### 2 期 内审准备

详细流程见 `references/phase2-internal-review.md`，要点：

- **送审前 3 天**：用 `references/review-checklist.md` 自查；用 `phase2-internal-review.md` 的"内审预演问题表"自问 20 个问题
- **会议组织**：议程模板、参会人员清单（部门技术负责人、项目经理、技术总工）
- **内审纪要回填**：用 `references/review-response-template.md` 的内审版样式逐条落实

### 3 期 专家评审与修订

延续现有 checklist 与回复模板：

- 送审材料组卷：方案正式版 + 内审意见回复 + 附图册 + 安评报告 + 施工方案摘要
- 高频意见对照：`references/review-checklist.md` 内"评审会议典型修改意见汇总"
- 回复表撰写：`references/review-response-template.md`，每条**必须**注明对应页码

## 两类方案模板（择一使用）

阅读本 skill 时务必先弄清楚用户场景属于哪一类。两类模板章节顺序和数量差异较大：

### 模板 A：运营分公司标准格式（**16 章**，重型，强制用于运营线路）
适用于既有运营线路（如宁波 1/2/3/6/7/8 号线已开通段）受外部施工影响时的方案。**必须**包含运营分公司要求的"轨行区作业管理""数据保密""与工程相关单位的配合"等章节。完整目录见 `references/toc-template-A.md`。

### 模板 B：设计院精简格式（**11–14 章**，轻型，适用于建设期线路）
适用于建设期/未运营线路、或工程量较小、由设计院出具的方案。完整目录见 `references/toc-template-B.md`。

> 默认按 **模板 A** 起草。如用户明确为建设期线路或要求简版，再切换到模板 B。

## 出稿后通用质量保障要点

- **章节编号与目录完全一致**，避免出现"3.2 → 3.4（跳号）"
- **图表必须有编号和题注**（图 X.X-1 XXX 示意图）
- **报警值表必须分项目、分阶段、分类型**——预警/报警/控制三栏不可合并
- **每个施工阶段的监测频率表都必须独立成表**（参考 6 号线望春桥方案，五个阶段五张表）
- **平面控制网与高程控制网必须分别给"基准点 / 工作基点 / 监测点"三级**
- **应急组织机构必须列出"地保办—地保车间—监测单位—施工方"四级**

## 输出格式建议

- 默认输出 **Markdown** (`.md`)，便于版本控制与后续转换
- 用户明确要 Word 文档时，先用 markdown 起稿，再通过 `pandoc` 转 `.docx`
- 附图先用文字描述位置（"详见图 5.1-1"），不强行插入图片
- 中文标点全部使用中文全角符号，规范名称用书名号《》

## 示例：典型工况快速选择

| 工况 | 必备监测项目 | 关键关注 |
|---|---|---|
| **基坑开挖**（紧邻既有线） | 沉降、水平位移、收敛、巡视；基坑围护抽测 | 开挖至坑底/换撑/拆撑阶段加密 |
| **顶管/盾构下穿** | 沉降、水平位移、收敛、静力水准（自动化） | 顶进至轴线/注浆置换/嵌缝阶段最敏感 |
| **管廊上跨** | 沉降、水平位移、收敛 | 卸土回弹与重车荷载分别加密 |
| **桥梁迁建** | 沉降、水平位移、收敛、振动 | 钢板桩打拔、桥桩施工、桥下通道开挖阶段 |
| **临近建筑施工** | 沉降、水平位移、巡视 | 重载车辆停放位置补充说明 |
| **盾构区间施工**（建设期） | 沉降、水平位移、收敛、振动、轨道几何 | 按工筹分阶段制定频率表 |
| **高架区间 / 出入场线**（桥梁还建、桥下基坑、管廊上跨、邻近桥桩） | 沉降（墩顶/墩底/盖梁/梁端）、水平位移、**桥墩倾斜**、巡视 | **不写"收敛"**；辅桥道床状态前置调查；首级控制点设桥外；登高+接触网约束；详 `references/elevated-line.md` |
