# RAILWISE Desktop Codex-Style Redesign

## Goal

把 RAILWISE Desktop 从“能力配置后台”改成“工程 AI 工作台”。用户打开软件后，第一眼只需要理解三件事：当前项目、要交给 RAILWISE 的任务、执行进展。智能体、Harness、Skills、工具、MCP、模型和权限仍然完整保留，但默认退到后台、侧栏、设置或能力市场中。

## Product Principle

Codex 的核心体验不是功能少，而是把复杂能力压进一个清晰的工作循环：

1. 选择项目上下文。
2. 输入任务。
3. 系统规划并执行。
4. 必要时请求权限。
5. 输出结果和交付物。

RAILWISE 必须采用同样的信息架构。专业能力要深，但主界面要极简。

## Target IA

### Primary Surface

第一屏只展示：

- 左侧项目栏：当前文件夹、最近项目、能力市场、设置入口。
- 中央任务流：对话区、任务输入框、推荐任务。
- 右侧执行抽屉：当前智能体、模型、权限、工具调用、交付物状态。

中央任务输入框是唯一主操作。用户不需要先理解 Harness、MCP 或 Skills 才能开始。

### Secondary Surface

以下能力从主流程移出：

- 专业智能体矩阵。
- 工具列表。
- Skills 列表。
- MCP 和模型 Provider。
- Harness Profile。
- 权限策略。

这些进入“能力市场”和“高级配置”。默认只显示少量状态摘要和入口。

### Advanced Surface

高级模式保留完整配置能力，用于实施人员、管理员和开发者：

- 智能体详情和模型绑定。
- Marketplace 安装/启用/停用。
- Harness 模式。
- 工具、Skills、MCP 明细。
- 日志和诊断。

高级模式不作为普通用户的起点。

## Visual Direction

界面语言参考 Codex：

- 更少卡片，更少说明文字。
- 中央输入框和对话区优先。
- 功能入口使用图标按钮、短标签和折叠面板。
- 状态用一行短文本表达，不用大面积指标卡。
- 避免“智能体数量”“工具数量”“Skills 数量”这类第一屏统计。
- 颜色克制，主色只用于开始按钮、焦点和选中状态。

## Functional Preservation

本次改版不删除任何能力：

- 仍支持项目文件夹选择和最近项目。
- 仍支持按选定智能体启动会话。
- 仍支持任务 handoff 到 session。
- 仍支持 Marketplace 本地预置和远程同步。
- 仍支持模型 Provider 接入和智能体模型路由。
- 仍支持 Harness 状态、权限、工具与 Skills 展示。
- 仍保留智能体详情页。

变化只发生在默认展示层：普通用户先看到任务协作，复杂能力按需展开。

## First Slice Scope

第一阶段只改 `/agents` 首页：

1. 把 header 改成简短工作台标题。
2. 将任务输入框提升为主视觉区域。
3. 删除第一屏长说明文案。
4. 把 Harness 调度预案折叠为“执行预览”。
5. 把专业智能体、工具、Skills、能力市场移入“能力与设置”次级区。
6. 保留现有 test id，避免破坏已覆盖流程。
7. 更新测试，确保能力仍存在但不强迫显示在第一屏。

## Acceptance Criteria

- 打开 `/agents` 后，用户能在首屏直接看到任务输入框和开始按钮。
- 首屏不再大面积展示智能体矩阵、工具列表、Skills 列表或能力市场卡片。
- “能力市场”和“高级配置”仍可展开访问。
- 项目文件夹选择、推荐任务、智能体选择、模型接入、Marketplace 操作仍可用。
- `packages/app` 相关测试通过。
- 桌面构建检查不因改版破坏。
